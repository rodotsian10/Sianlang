# SianLang 1st Game 수정 체크리스트

## 2026-09-18 수정 결과

- 플레이어 시작 위치 설정을 `initialized` 조건으로 묶어 장면 진입 후 한 번만 실행하도록 수정했다. `var` 선언은 기존 엔진에서 이미 첫 프레임에만 실행되고 값을 유지하므로 새 장면 문법은 필요하지 않았다.
- 게임 루프는 입력·코드·그리기에 소요된 시간을 제외한 남은 시간만 기다린다. 이동 거리는 `game.delta_time()`으로 계산한다.
- VS Code 확장은 실행하는 `.sian` 파일의 폴더를 작업 폴더로 사용한다. 상대 경로로 설정한 인터프리터 위치는 여전히 워크스페이스 폴더를 기준으로 해석한다.
- 이 PC에 설치된 VS Code 확장을 게임 문법이 포함된 0.5.0으로 갱신했다. 열린 VS Code 창에서는 `Developer: Reload Window`가 필요할 수 있다.
- 위치 유지, 게임 기능, 기존 런타임, 확장 실행 경로 테스트를 통과했다.

아래 내용은 당시 문제를 기록한 원래 체크리스트다. 초기화용 새 문법이나 엔진의 자동 초기화 단계는 이번 수정에 포함하지 않았다.

## 1. 장면 초기화와 프레임 코드 분리

현재 `scene`의 본문은 게임이 실행되는 동안 매 프레임 반복된다.
이 구조 자체는 게임에 필요하지만, 초기화 코드까지 반복되는 문제가 있다.

현재 발생하는 문제:

```sian
scene play
    var player = rodot.load("player.rodot")
    player.x = 100

    if key.down("right")
        player.x += player.speed
```

매 프레임 `player.x = 100`이 먼저 실행되므로 캐릭터가 이동하지 못하고 원래 위치로 돌아온다.

수정 방향:

- 장면에 처음 진입했을 때 실행하는 초기화 단계 추가
- 변수 선언, `rodot.load`, 시작 위치·크기·속도 설정은 한 번만 실행
- 키 입력, 이동, 충돌, `draw.` 명령은 매 프레임 실행
- `scene.change()`로 다시 들어오면 해당 장면의 초기화는 다시 실행
- 장면을 나갈 때 이전 장면의 환경과 스프라이트를 정리

가능한 내부 구조:

```text
장면 진입
    초기화 코드 1회 실행

매 프레임
    장면 업데이트 코드 실행
    화면 자동 렌더링
```

문법을 새로 만들지 않고 엔진에서 우선 처리한다. 나중에 필요하면 `scene title` 아래에서 초기화와 업데이트를 명확히 표시하는 문법을 추가할 수 있다.

## 2. FPS 및 화면 끊김 수정

현재 게임 루프는 프레임 코드를 실행한 뒤 `Sleep(1000 / fps)`를 추가로 기다린다.
따라서 실제 프레임 시간은 다음과 같다.

```text
코드 실행 시간 + 고정 Sleep 시간
```

이 방식은 목표 FPS보다 느려지고 움직임이 끊길 수 있다.

수정 방향:

- 프레임 시작 시간을 기록
- 입력·장면 코드·렌더링 시간을 측정
- 목표 프레임 시간에서 이미 사용한 시간을 뺀 만큼만 대기
- 목표 시간을 넘긴 경우에는 대기하지 않고 다음 프레임 실행
- `game.delta_time()`이 실제 프레임 경과 시간을 반환하는지 확인
- 너무 큰 지연이 발생하면 delta time에 상한을 적용할지 검토
- `InvalidateRect`와 `UpdateWindow` 사용을 확인해 불필요한 중복 렌더링을 줄임

목표:

```text
game.fps = 60
약 16.67ms마다 한 프레임
```

## 3. VS Code 실행 버튼 오류 수정

현재 확장 프로그램은 VS Code에서 선택한 파일이 속한 워크스페이스 폴더를 실행 경로(`cwd`)로 사용한다.

따라서 프로젝트 루트를 열 때와 `sianlang1stgame` 폴더만 열 때 상대 경로가 달라진다.

현재 게임 코드:

```sian
rodot.load("sianlang1stgame/player.rodot")
```

프로젝트 루트에서 실행하면 정상이다. 하지만 `sianlang1stgame` 폴더를 워크스페이스로 열면 다음 경로를 찾게 된다.

```text
sianlang1stgame/sianlang1stgame/player.rodot
```

수정 방향:

- 리소스 경로 기준을 명확히 정한다.
- 기본 기준은 실행하는 `.sian` 파일이 있는 폴더로 검토한다.
- 또는 프로젝트 루트 기준 리소스 탐색 규칙을 추가한다.
- VS Code 확장이 실행 전 작업 폴더와 실제 리소스 경로를 일치시킨다.
- 인터프리터 오류 메시지에 실제로 찾은 경로를 표시한다.
- `.rodot` 파일을 찾지 못했을 때 `파일 없음`과 `문법 오류`를 구분한다.

확장 프로그램 확인 항목:

- 번들 인터프리터 경로: `sianlang-vscode/bin/win32-x64/Sianlang.exe`
- 저장되지 않은 파일 실행 차단
- 워크스페이스 신뢰 여부
- `.sian` 파일 저장 후 실행 여부
- 파일 경로에 공백·한글·특수문자가 있을 때 실행 여부

## 4. `.rodot` 생성 및 실행 파일 경로

- `Conversion.sian`을 어느 폴더에서 실행해도 예상한 출력 위치에 생성되는지 확인
- 기존 `.rodot` 파일을 덮어쓰지 않는 동작 유지
- 게임 실행 시 `.rodot`을 읽지 못하면 원인과 경로를 함께 출력
- PNG 원본 경로와 `.rodot` 경로를 상대 경로·절대 경로 모두 테스트

## 5. 게임 예제 수정

엔진 수정 후 `game.sian`은 초기화 코드와 프레임 코드를 분리한 방식으로 다시 검증한다.

검증할 항목:

- 플레이어가 방향키를 누르는 동안 자연스럽게 이동하는가
- 이동 후 다음 프레임에도 위치가 유지되는가
- 목표물과 충돌했을 때 점수가 바뀌는가
- 장면을 다시 시작하면 플레이어가 초기 위치로 돌아가는가
- `Q` 키로 게임이 정상 종료되는가
- 60FPS와 낮은 FPS에서 이동 속도가 지나치게 달라지지 않는가

## 6. 테스트 추가

- 장면 초기화 코드가 한 번만 실행되는 테스트
- 장면 본문이 여러 프레임 실행되는 테스트
- 초기화 후 `player.x`가 이동으로 유지되는 테스트
- 실제 FPS 대기 시간 테스트
- `SIAN_HEADLESS=1` 게임 루프 테스트
- VS Code 실행 버튼의 프로젝트 루트 실행 테스트
- VS Code에서 `sianlang1stgame` 폴더만 연 실행 테스트
- 잘못된 `.rodot` 경로의 오류 메시지 테스트
- 공백이 포함된 경로 테스트
